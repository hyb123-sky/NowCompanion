# Now Companion：陪伴式企业桌宠 UI 方向

> **用途**：这是交给 UI 美术、动效与后续实现人员的视觉方向稿，不是前端实现规范，也不包含业务逻辑或数据模型。

## 1. 研究结论与设计取向

本方向把用户提到的 Grok Bot、腾讯 Marvis 以及当前主流 AI Agent 的体验拆解为可借鉴的**交互品质**，而不是复刻任何单一产品的角色、图形或界面：

| 可借鉴的品质 | 转化为 Now Companion 的设计原则 | 不要照搬 |
| --- | --- | --- |
| AI Agent 的即时可用性 | 伴侣始终呈现“正在理解工作环境”的低干扰状态；需要时一键展开为简洁的任务对话。 | 大面积聊天网页、信息瀑布。 |
| 陪伴型角色的生命感 | 用呼吸、视线、姿态、光晕和节奏表达状态，而非用大量文字或夸张表情。 | 具体角色轮廓、五官比例、IP 性格与口头禅。 |
| 高级科技产品的克制 | 低饱和深色基底、少量冷白和一枚可配置的状态色；信息分层而非装饰堆叠。 | 荧光渐变、赛博噪点、游戏化徽章墙。 |
| 企业 Agent 的可信度 | 重要性由空间、节奏、可读性和明确来源表现；每个主动提示都可查看、暂缓或静音。 | “人格化”替代事实、情绪化恐吓、无法关闭的打扰。 |

**一句话方向**：它不是一个固定摆件，也不是一个缩小版聊天窗口；它是一个会留意、会等待、会在合适时机轻声提醒的工作伙伴。

## 2. 核心视觉概念：Quiet Current（静流）

以 Logo 的深海军蓝、柔和鼠尾草绿和圆滑字形作为抽象灵感：一个带有柔软轮廓、低频呼吸感的“静流核心”，让工作信号以克制的层次、方向与密度靠近它。它不使用黑洞、太空、宇航或科幻 HUD 的视觉隐喻。

- **主体**：悬浮的深海军蓝软质形体，可是 3D 软胶、Live2D 非人形角色，或极简程序化形体；主体在不同状态中会伸展、收拢或轻微前倾，不能锁死为一张固定 PNG。
- **眼睛**：两枚深色、半嵌入的观察点，仅通过轻微高光、瞳孔偏移、半眨和闭合传达注意力。它们不应是卡通大眼，也不使用持续凝视。
- **流线**：只在“捕捉到事项”“思考”“紧急”状态出现。流线来自 Logo 中的方向感，代表被关注的信号，不代表任务数量。
- **光**：状态光贴近边缘和环境，不从角色正面喷射。亮度应小于屏幕主内容的视觉权重。
- **材质**：深海军蓝、雾面软胶、柔和玻璃和极细的冷色边缘反射；避免机械金属、天体、宇航服或科幻 HUD。

## 3. 视觉系统

### 色彩

| Token | 建议色值 | 用途 |
| --- | --- | --- |
| `Void 950` | `#05090D` | 核心阴影、深层背景。 |
| `Midnight 800` | `#0C1B28` | 容器及角色暗部。 |
| `Harbor 600` | `#1D3A50` | 角色受光面、展开面板。 |
| `Mist 50` | `#F2F6F3` | 关键正文与高对比图标。 |
| `Quiet Sage 400` | `#8FAE91` | 默认健康、可用与完成状态。 |
| `Amber 400` | `#E5B96C` | 需要留意，非紧急。 |
| `Signal 450` | `#D97A70` | 仅限需要立即处理的状态。 |

状态色必须支持由租户品牌或无障碍策略覆盖。颜色永远不是唯一状态载体：同时使用姿态、图标、标题和简短文本。

### 排版与形状

- 信息字体：系统无衬线字体；标题使用 14–16 px，辅助说明 12–13 px，不使用“AI 感”展示字体。
- 容器：24–32 px 圆角；气泡 16–20 px 圆角；只保留一层半透明表面，不做多层玻璃叠加。
- 间距：采用 8 px 基准，角色周围至少保留 24 px 呼吸区。
- 阴影：大而软、透明度低。阴影用于悬浮关系，不能形成黑色硬边。

## 4. 状态机：角色如何“活着”

状态是连续的视觉行为，不是切换多张立绘。一个状态最多同时激活一种主光色和一种运动。

| 状态 | 触发感受 | 角色行为 | 信息层 |
| --- | --- | --- | --- |
| **静候 / Idle** | 没有待处理提醒。 | 5–7 秒一轮极慢呼吸；偶发微小视线漂移。 | 不显示气泡，只留极弱健康点。 |
| **感知 / Listening** | 用户靠近、唤起或打开工作上下文。 | 眼睛轻微向交互来源移动，边缘光增加 10–15%。 | 显示一句可行动问候，不主动弹出任务。 |
| **思考 / Thinking** | 用户请求总结、检索或等待结果。 | 流线缓慢聚合，眼睛半闭，不使用转圈 loading 图标。 | 一行可取消的进度文字。 |
| **关注 / Attention** | 有待处理但不紧急的新事项。 | 轻微前倾、1 次淡入的鼠尾草流线脉冲。 | 最多一张 2 行摘要卡。 |
| **提醒 / Alert** | 临近阈值或需要处理。 | 呼吸速度略提高，琥珀边缘光只闪一次后保持稳定。 | 明确事项、原因、主操作、稍后提醒。 |
| **紧急 / Urgent** | 已越过策略定义的紧急阈值。 | 角色靠近前景；不抖动、不连续闪红。 | 单一优先事项，主操作始终可见。 |
| **专注 / Focus** | 用户设置免打扰或专注。 | 眼睛闭合，主体降低对比度，流线消失。 | 只保留可恢复的细小月牙标记。 |

## 5. 主动交互的层级

### A. 环境态（默认）

桌宠固定在屏幕边缘的安全区域，推荐直径 **120–176 px**。只有角色与一个不打扰工作的健康点；它不显示任务计数、长文或常驻控制条。

### B. 轻提示（由角色发起）

角色向屏幕内侧探出一张窄气泡卡，宽度 **280–340 px**。一张卡只回答四件事：

1. 发生了什么；
2. 为什么现在值得注意；
3. 一个最合适的下一步；
4. “稍后”或“静音”出口。

气泡从角色旁边生长，不遮挡角色。用户忽略后 8–12 秒退回环境态；高优先级项目只降低透明度、不自动消失。

### C. 工作台（由用户发起）

点击角色或气泡后，展开为屏幕侧边的 **360–440 px** 工作台。角色保持在顶部或侧边并继续低频反馈，下面才是对话、队列摘要与操作。工作台不是全屏聊天应用；每次只聚焦一个工作目标。

## 6. 企业级克制：必须遵守的边界

- 主动提醒由策略决定，角色只负责表达，不“猜测紧急度”。
- 文案基于事实：避免“我发现了一个可怕的问题”等拟人化夸张语言；使用“有一项 SLA 将在 20 分钟后到期”。
- 不在环境态显示敏感记录字段、客户名或长标题；详细信息只能在用户主动展开后出现。
- 提供三个稳定入口：**查看详情**、**稍后提醒**、**静音/专注**。不隐藏关闭方式。
- 动效尊重“减少动态效果”系统设置；紧急状态也禁止抖动、闪烁和连续播放音效。
- 角色的情绪不评价用户表现。它表达的是系统的注意力与可用性，而不是“开心/失望”。

## 7. 初版美术交付清单

交给后续实现前，应该先完成以下纯视觉资产与稿件：

1. **角色形体板**：正面、左/右 15°、轻前倾、闭眼、半眨各一张；保持同一深海军蓝软质主体。
2. **状态板**：静候、感知、思考、关注、提醒、紧急、专注各一张；呈现光、流线、眼睛和姿态差异。
3. **三张场景稿**：屏幕边缘环境态、轻提示、展开工作台，使用同一个角色比例与色彩体系。
4. **动态节奏表**：标注呼吸、眨眼、视线、流线和提示卡出现/消失的时长与缓动；不要求实现代码。
5. **可访问性板**：高对比模式、减少动态效果、色觉差异下的三种关键状态。

## 8. 下一步建议

在开始第二版视觉稿前，应先用这份方向制作 **3 个静态场景而非 1 个固定窗口**：

- 场景 1：静候中的环境态，证明它可以长期停留而不抢夺注意力；
- 场景 2：一项“需要关注”的工作提示，证明它能温和地主动协助；
- 场景 3：展开后的工作台，证明角色和企业信息可以共存且保持专业。

选定角色形体与一个状态色方向后，再由美工制作角色状态板；实现人员随后可将状态板和节奏表映射到实际桌宠框架。
